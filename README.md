# Butaq — голосовой маршрутизатор страховых обращений

Проект для кейса **Voice Router** хакатона HackAlem AI / Halyk Bank. Butaq помогает клиенту страховой компании сформулировать запрос голосом или текстом, определяет подходящий сценарий из каталога и отвечает на русском или казахском языке. Пользователь видит расшифровку диалога и причину выбора сценария. Это демонстрационная система: она не выполняет операции со страховыми договорами.

## Что реализовано

- Голосовой и текстовый диалог в браузере на странице `/voice/`: потоковая расшифровка речи, озвученный ответ, возможность прервать ответ и сменить тему. При ошибке потокового соединения доступна отправка текста через обычный HTTP-запрос по явному действию пользователя.
- Два AI-этапа: **Router** выбирает сценарий из актуального каталога или запрашивает уточнение, **Resolution** формирует ответ на основе выбранного сценария, базы знаний и разрешённых инструментов чтения демонстрационных записей. Решение содержит причину выбора, альтернативы и измеренные времена этапов.
- Учёт контекста разговора: активного сценария, отложенных тем и последних реплик. Если запрос остаётся неопределённым, система предлагает обратиться к оператору; фактического соединения с оператором нет.
- Панель `/admin/` для изменения сценариев, промптов, модели и порога уверенности, а также импорта набора JSON-файлов. Доступ по токену администратора; реализованы также вход по passkey (WebAuthn) и распознаванию лица (InsightFace).
- HTTP API для текстовых и файловых голосовых запросов, WebSocket API для потокового разговора. Подключён адаптер входящих звонков SignalWire к общему мультиагентному сервису; подробнее в [документации телефонии](docs/telephony.md).

## Как работает решение

1. Пользователь говорит или вводит сообщение на `/voice/`. В потоковом режиме браузер передаёт звук по WebSocket, а сервер получает промежуточную и финальную расшифровку через OpenAI. Для файлового API `/router/voice` сначала распознаётся завершённая аудиозапись.
2. Router получает текст, контекст беседы и текущий каталог из PostgreSQL. Его структурированное решение проверяется: выбранный ID должен присутствовать в каталоге, а уверенность сравнивается с настроенным порогом.
3. Если сценарий выбран, Resolution использует его описание и доступные справочные данные для ответа. Если информации недостаточно, система уточняет запрос; при невозможности продолжить сообщает о необходимости помощи человека.
4. Интерфейс показывает текст ответа, сценарий и обоснование; голосовой ответ синтезируется и воспроизводится. Правки каталога и настроек из панели учитываются при следующем обращении.

## Технологии и архитектура

| Компонент | Реализация |
| --- | --- |
| Интерфейс | TypeScript, React, Next.js, Tailwind CSS; браузерные AudioWorklet и Web Audio API |
| Backend и API | Python, FastAPI, WebSocket; пакет `app/` |
| AI-маршрутизация | OpenAI Agents SDK, два агента Router → Resolution в `multi-agent/`; модель задаётся `ROUTER_MODEL` и может меняться в админ-панели |
| Речь | OpenAI API: потоковая транскрипция через `MULTI_AGENT_TRANSCRIBE_MODEL`, файловая через `V2V_TRANSCRIBE_MODEL`, синтез через `V2V_TTS_MODEL`; код в `multi-agent/` и `v2v/` |
| Данные | PostgreSQL, SQLAlchemy, Alembic; каталог, настройки и записи для Face ID |
| Доступ администратора | Токен, WebAuthn/passkey, InsightFace и ONNX Runtime для локального распознавания лица (`faceid/`) |
| Развёртывание | Docker Compose: backend, PostgreSQL, статический frontend под Caddy; Caddy проксирует `/router/*` на API |

Схема основного пути: **браузер → Caddy → FastAPI → распознавание речи (если нужен голос) → Router → Resolution → синтез речи → браузер**. Каталог и настройки читаются из PostgreSQL; контекст активных разговоров хранится в памяти процесса backend. Пакет `telephony/` и адаптер `app/phone/` подключают входящие звонки SignalWire через GPT-Live к тому же RouterService; включение управляется `TELEPHONY_ENABLED`.

## Установка и запуск

Нужны **Docker с Compose**, Git и ключ OpenAI API с доступом к моделям, указанным в [`.env.example`](.env.example). Выполните в корне репозитория:

```bash
cp .env.example .env
# В .env укажите реальные V2V_API_KEY, ROUTER_ADMIN_TOKEN и POSTGRES_PASSWORD.
# Для локальной проверки оставьте FRONTEND_ORIGINS и ROUTER_WEBAUTHN_ORIGIN
# со значениями localhost из .env.example.
make up
docker compose ps
```

После запуска откройте **http://localhost:3000/voice/** (страница проекта — http://localhost:3000/). Backend доступен на `http://localhost:8000`, документация API — на `http://localhost:8000/docs`. При старте backend применяет миграции; при первом обращении к API пустая база получает демонстрационный каталог. Веб-камере и микрофону требуется разрешение браузера; доступ к микрофону разрешён на localhost или по HTTPS.

Остановить сервисы можно командой `make down` (том PostgreSQL сохраняется); логи — `make logs`. Для запуска на сервере установите `ROUTER_WEBAUTHN_ORIGIN` в точный публичный origin и добавьте его в `FRONTEND_ORIGINS`. На уже заполненной базе `ROUTER_MODEL` и `ROUTER_CONFIDENCE_THRESHOLD` из `.env` **не перезаписывают** сохранённые настройки: изменяйте их на `/admin/` или через API. Файл `.env` содержит секреты и не должен попадать в Git.

## Как проверить решение

1. Убедитесь, что API отвечает:

   ```bash
   curl http://localhost:8000/health
   # {"status":"ok"}
   ```

2. Откройте http://localhost:3000/voice/. При первом обращении загрузится демонстрационный каталог из 40 сценариев. Нажмите **Talk to Butaq**, разрешите доступ к микрофону и скажите, например: «По заявке DEMO-A-2001 деньги списались, а полиса нет». Можно ввести тот же текст в поле сообщения. Посмотрите расшифровку, ответ и карточку выбора сценария; затем задайте уточняющий вопрос или перебейте ответ. Для этих запросов нужен действующий ключ OpenAI.
3. Альтернатива без микрофона — отправить текст напрямую:

   ```bash
   curl -sS http://localhost:8000/router/text \
     -H 'Content-Type: application/json' \
     -d '{"session_id":"jury-demo","text":"По заявке DEMO-A-2001 деньги списались, а полиса нет","synthesize":false}'
   ```

   Ответ содержит поля `transcript`, `reply`, `action`, `scenario_id`, `confidence` и `timings`. Конкретный ответ модели и выбранное действие могут меняться. Доступный каталог можно посмотреть через `GET /router/scenarios`; панель администратора — на http://localhost:3000/admin/.

Для проверки без платных вызовов моделей в локальном окружении доступны тесты (нужны Python, Node.js и запущенный PostgreSQL):

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
TEST_DATABASE_URL=postgresql+psycopg://butaq:YOUR_POSTGRES_PASSWORD@localhost:5433/butaq python -m pytest -q
cd frontend && npm ci && npm run typecheck && npm run test:voice
```

Тесты backend создают изолированную схему в PostgreSQL; для проверки модели и звука применяются заглушки. Пароль в `TEST_DATABASE_URL` должен совпадать с `.env`.

## Данные и внешние сервисы

- По умолчанию используется **авторский синтетический** набор `app/data/demo/`: 40 страховых сценариев, справочные сведения, вымышленные записи клиентов, примеры диалогов и тестовые фразы. Описания и инструменты не заменяют реальную страховую систему.
- В `app/data/prod/{auto,health,travel}/` лежат три независимых синтетических набора (авто-, медицинское и туристическое страхование). Они **не загружаются автоматически**: администратор может импортировать один согласованный набор через `POST /router/admin/catalog/import-files`. Подробности — в [описании данных](app/data/README.md).
- Внешний OpenAI API нужен для распознавания речи, работы агентов и озвучки; доступность и стоимость зависят от выбранных моделей и учётной записи. InsightFace при первом использовании загружает локальную модель распознавания лиц. Исходный шаблон главной страницы также использует внешние медиа- и шрифтовые ресурсы.
- Интеграция с SignalWire/OpenAI для входящих звонков описана в [docs/telephony.md](docs/telephony.md), и включается через `TELEPHONY_ENABLED=true` после настройки credentials и вебхуков.

## Известные ограничения

- Данные демонстрационные; в репозитории нет подтверждения загрузки официального набора организаторов или подключения реальной страховой базы. Оплата, изменение полиса, отмена услуги и другие действия над клиентским счётом не выполняются.
- `handoff` означает рекомендацию обратиться к оператору, **не** фактический перевод звонка. Телефонный адаптер не настроен для реальных вызовов: номер и подтверждённая проверка звонка отсутствуют.
- Контекст разговора находится в памяти одного процесса backend и пропадает после перезапуска. Оценка уверенности приходит от модели, не является статистически откалиброванной вероятностью; время ответа зависит от сети и OpenAI, без гарантированных задержек.
- Распознавание лица по изображению подвержено подмене; для более надёжного входа поддерживаются passkey. Для работы голосового сценария нужны интернет и доступ к внешним моделям.

## Развёрнутая версия

**https://owlpeer.com/voice/** — страница голосового интерфейса; **https://owlpeer.com/** — главная. Публичные страницы и `/health` доступны по HTTPS. Наличие публичной страницы само по себе не подтверждает выполнение платных AI-запросов или работоспособность опциональной телефонии; для полной демонстрации используйте шаги проверки выше.
