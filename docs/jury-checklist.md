# Проверка перед демонстрацией

## Подготовка

1. `make up`; дождаться healthy backend. Если порты заняты другим проектом, сначала согласовать его остановку — не удалять чужие контейнеры или тома.
2. `make validate-official`, затем **явно** `make import-official` на выбранной тестовой БД. Импорт заменяет текущие сценарии и справочные данные; нужные правки сохранить заранее.
3. Проверить `/router/catalog/status`: `official_ids_complete`, `knowledge_loaded`, `records_loaded` — true. Проверить баннер на `/voice/`. `/health` не проверяет ключи или доступ к моделям.
4. На сервере нужны HTTPS, правильный DNS, открытые 80/443 и исходящий доступ к OpenAI. Проверять реальные запросы после деплоя, а не только страницу.
5. Использовать только вымышленные идентификаторы из набора. Подготовить наушники. Телефония и реальное соединение с оператором для веб-демонстрации не нужны и не включены.

## Содержательные проверки

Это ручной smoke-тест, не результаты уже выполненного прогона. Ожидаемые сценарии следуют границам каталога. Модель может ошибиться — фиксируйте это в отчёте, не меняйте метки под результат.

| Запрос / действие | Что проверить |
| --- | --- |
| «Сколько стоит ОГПО?» | SC01, запрос недостающих параметров, без выдуманной цены |
| «Я только что попал в ДТП, стою на месте» | SC11, приоритет безопасности |
| «Выплату одобрили, но сумма слишком маленькая» | SC19, не SC17 |
| «Ақша шегерілді, бірақ полис шықпады» | SC30, ответ на казахском |
| «Полисім қашан аяқталады? Номер SQ-OGPO-104501» | SC25, mixed/KK без случайного переключения сценария, даты из записи |
| «Нужно продлить полис, ещё водителя добавить» | SC27 + отложенный SC04 |
| Затем «Сначала добавим водителя», потом «Вернёмся к продлению» | Switch/resume, параметры и история не теряются |
| «Я по поводу страховки» | Уточнение, не уверенное угадывание |
| «Мой телефон +77010000099» при запросе статуса | Запись не найдена, не подставлять другого клиента |
| «Соедините с человеком» | SC37/сообщение о необходимости специалиста; не обещать состоявшийся перевод |

Отдельно пройти 10 диалогов `dialogs_sample.json` с сохранением одной сессии на диалог. Образцы содержат исполняемые mock-действия: текущий режим read-only должен честно сказать, что операция не выполнена, даже после подтверждения.

## Стабильность UI и звука

- Проверить Chrome и Safari, узкий экран 375 px и desktop. Кнопки, поле, история и трассировка доступны с клавиатуры; нет горизонтального скролла.
- Запретить микрофон: понятная ошибка, текст остаётся доступным. Разрешить и подключиться повторно.
- Произнести 10 реплик, сделать паузу, перебить ответ голосом и кнопкой. Не должно быть самопроизвольных переподключений, двойного ответа или потери начала фразы.
- Выключить микрофон кнопкой: ответ ещё слышен, пользовательский звук не передаётся. Включить без новой сессии.
- Завершить разговор и открыть снова пять раз: индикатор микрофона гаснет, session-busy не остаётся навсегда.
- Отключить сеть при отправке текста: черновик остаётся, автоповтора нет. Тайм-аут не доказывает, что запрос не был принят; перед ручным повтором проверить историю.
- Выбрать старую реплику: её сценарий и время не подменяются последним ответом. Экспорт соответствует истории, без аудиоданных.
- Записать реальный замер конец речи → первый слышимый звук отдельно. Не выдавать backend total за этот показатель. STT/TTS Live пока не измеряются отдельно.

## Артефакты

- Запустить `pytest`, frontend tests/typecheck/build и записать результаты со списком пропущенных проверок.
- На согласованном тестовом окружении выполнить `python -m app.evaluate_dataset case_2/voice_router_dataset --run-models --output /tmp/butaq-eval-new`; это платные вызовы.
- Сохранить отчёт, версию каталога, модель, commit SHA и JSON трассировки. Не публиковать ключи, токены или реальные данные.
- На защите показать Router → Resolution, а не только говорящий orb. Отдельно назвать ограничения: read-only действия, отсутствие оператора, память сессии одного процесса и незамеренные голосовые задержки.
