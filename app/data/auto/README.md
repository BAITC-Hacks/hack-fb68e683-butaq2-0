# Автострахование — Butaq Motor Demo

Самостоятельный **синтетический** набор для Case 2 Voice Router. Версия: `butaq-auto-1`. Это не официальный starter kit и не данные реального страховщика.

## Состав

- `scenarios.json`: 40 сценариев AUT01–AUT40; назначение, границы, параметры, действия, примеры запросов и ответов RU/KK.
- `dialogs_sample.json`: 10 размеченных диалогов; смешанная речь, смена темы и возврат, неоднозначность, безопасность. Последний диалог содержит 10 ходов.
- `knowledge_base.json`: вымышленная компания, продукты, ограничения и факты процедур для ответов.
- `mock_backend.json`: связанные тестовые клиенты, договоры, обращения и статусы. Это JSON-снимок, не сервер исполнения операций.
- `dev_utterances.json`: 48 реплик, независимо перефразированных относительно примеров каталога; все 40 намерений и 8 дополнительных проверок.
- `evaluate.py`: автономный скрипт Python 3.10+ без внешних зависимостей; запуск без `--live` не обращается к сети.

## Что можно спросить

1. «По AUTO-A1 деньги сняли, полиса нет. Потом поменяем адрес AUTO-L1.»
2. «Алдымен AUTO-L1 мекенжайын Демо-көше 8 деп өзгертейік.»
3. «Вернёмся к оплате AUTO-A1.»

## Тестовые записи

AUTO-A1 — платёж 120 000 ₸ получен, полис ожидает выпуска; AUTO-P1 — активный Motor Plus; AUTO-C1 — нет фото; AUTO-C3 — одобрено 180 000 ₸, выплата не отправлена; AUTO-C4 — отказ из-за даты; AUTO-I1 — осмотр 25 сентября; AUTO-REP1 — ожидание детали; AUTO-L1 — документ готовится к отправке.

Все статусы относятся к **2026-09-23 09:00 Asia/Almaty**. Неизвестный ID не подменяется похожим: требуется уточнение. Один клиент может иметь несколько договоров и заявок; связь определяется идентификаторами, а не порядком записей.

## Безопасность и разметка

Для AUT24 (опасность), AUT40 (оператор) ожидается `action=handoff, scenario_id=null`, хотя эти намерения описаны отдельными строками каталога. Прямой запрос человека не считается обычным маршрутом.

Ясное намерение с недостающим ID остаётся соответствующим сценарием; ответ запрашивает параметр. Неоднозначное намерение получает `clarify`. Повторная неопределённость в диалоге приводит к `handoff`, как в текущем сервисе.

`expected_pending` задаёт минимальное множество отложенных тем; отсутствие или пустой список не требует очистки всех тем. `response_checks` — критерии **ручной** проверки ответа, а не автоматически пройденные тесты. Правильный scenario_id не доказывает безопасность ответа.

Данные только для чтения. Даже после подтверждения пользователя нельзя заявлять об исполнении: не списываются деньги, не меняются договоры, не бронируются услуги и не подключается оператор. Реальные персональные или медицинские данные не используются.

## Оценка

Из корня репозитория:

```bash
python app/data/prod/auto/evaluate.py --limit 48
python app/data/prod/auto/evaluate.py --dialogs --limit 10
# После осознанного импорта этого набора в отдельный тестовый backend:
python app/data/prod/auto/evaluate.py --live --limit 48
python app/data/prod/auto/evaluate.py --live --dialogs --limit 10
```

Импорт всех трёх файлов каталога/знаний/mock заменяет текущие данные и требует административной авторизации через существующий API. Подробности в [общем README](../README.md). Скрипт ничего не импортирует, проверяет активные IDs и содержимое сценариев, но не может подтвердить совпадение закрытых KB/mock через публичный API. Загружайте согласованный комплект целиком.

Live-запуск использует LLM backend, создаёт новые тестовые сессии и может расходовать баланс. Ответы не озвучиваются; STT/TTS здесь не измеряются. Ожидаемые метки не передаются модели. Ошибки HTTP/формата считаются промахами; отчёт показывает точность выбора, отложенные темы и фактическое время маршрутизации. Полного live-прогона этого набора при создании файлов не проводилось.
